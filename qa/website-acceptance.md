# 行程配對網站驗收

測試日期 2026-11-21（台北）。入口為根目錄的 `index.html`。研究資料採 `research/travel-data.json` 的 `schemaVersion: 1`，展示方案採 `data/mock/plans-模擬資料.json`。

初次驗收以無頭 Chrome 載入頁面與 JSON，測試時將台北日期固定為 2026-11-21。每個測試寬度各執行 19 項瀏覽器斷言。

離線開啟修正後，以 Chrome 預設本機檔案權限重新測試。直接開啟 `index.html` 可載入三張週報卡片並取得親子推薦。HTTP 模式繼續讀取原始 JSON，更新原始 JSON 時須同步更新首頁的離線快照。

| 案例 | 實測結果 |
| --- | --- |
| 週報與表單 | 三類入口均載入，可看到官方來源、即將開始與木棧道通行待確認狀態。空表單顯示欄位錯誤。 |
| 三類客群 | 親子得到宜蘭、情侶得到日月潭、熟齡得到故宮南院的模擬方案。親子結果顯示推薦理由與研究來源。 |
| 預算及零結果 | 四人兩天、NT$16,000 可入選。NT$15,999 顯示超出預算並保留輸入。測試資料的 NT$16,001 與缺價方案未入選。 |
| 必要限制與排序 | 目的地不符、出發地不符、步行超限或缺少必需設施時顯示原因。測試資料依風格命中數、價格及 ID 排序，只保留前三筆。 |
| 日期與資料狀態 | 以旅程第 2 天測試活動截止日當天與隔天。到期或木棧道待確認方案被排除。 |
| 模式及抓取失敗 | 正式模式沒有模擬推薦。注入讀取失敗時顯示重試，資料恢復後回到正常零結果。 |
| 諮詢摘要 | 選入方案後，摘要含方案名稱與模擬標示。替換 Clipboard API 驗證傳入內容與失敗時的手動選取。 |
| 響應式版型 | 320、768、1280 CSS px 分別顯示一、二、三欄，三種寬度皆無頁面水平溢出。 |

尚未驗證實機手機與平板、其他瀏覽器、完整鍵盤與讀屏操作、系統剪貼簿實際寫入、HTTP 部署環境與旅行社正式方案。正式發布前由旅行社補齊報價及成行資料，並依 PRD 重新查核易變資訊。

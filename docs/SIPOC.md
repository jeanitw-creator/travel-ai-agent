# SIPOC｜旅行社獲客網站

| SIPOC | 本課程定義 | 第一版的內容與責任 |
| --- | --- | --- |
| Supplier 供應者 | 旅行社、觀光署、活動主辦單位。 | 旅行社提供方案、計價範圍與查核紀錄。交通部觀光署及其開放資料提供景點線索。活動主辦單位提供展期、場次與異動公告。 |
| Input 輸入 | 旅遊資料、客戶偏好、行程條件。 | 旅遊資料附研究 ID、來源網址、查詢日及狀態。旅客填對象、人數、全團預算、天數、風格、日期，可指定目的地、出發地及步行或設施限制。旅行社提供報價口徑、停留日、動線與適用條件。 |
| Process 流程 | 選擇需求 → 比對方案 → 生成推薦。 | 先檢查表單，再比對方案的新鮮度、日期、全團預算與其他硬性條件。符合者依風格排序，前端組成推薦理由；無符合者顯示原因及可修改的欄位。 |
| Output 輸出 | 旅遊提案、行程介紹、諮詢內容。 | 旅遊提案是最多三張推薦卡和詳情；行程介紹包含分日安排、費用範圍與來源；諮詢內容是旅客可複製的偏好摘要，由旅客自行轉交。 |
| Customer 顧客 | 親子、情侶、熟齡旅客。 | 親子看主題與休息安排，情侶看興趣與活動強度，熟齡看步行、休息和必要設施。旅客可以查看推薦或諮詢流程。 |

## 交接與例外

| 節點 | 負責人 | 交付與把關 |
| --- | --- | --- |
| 素材交接 | 旅遊研究員 → 週報編輯 | 提供已核對內容、來源與日期。高美濕地木棧道在到訪日可通行前列為待確認。 |
| 上架交接 | 週報編輯、旅行社方案負責人 → 網站工程師 | 週報與研究資料提供行程素材。實際推薦另需要有價格口徑、適用人數與有效期限的方案資料；缺欄位須先補查。 |
| 旅客操作 | 網站工程師 → 旅客 | 推薦頁須呈現理由、價格包含及不含項目、查詢日與原始來源。沒有符合結果時，保留輸入並提供修正與諮詢入口。 |
| 諮詢與驗收 | 旅客 → 旅行社；驗收員核對流程 | 旅客可複製摘要並自行聯繫。驗收員確認無自動傳送、無聯絡資料留存，並測試零結果、過期及待確認狀態。 |

交付網站工程師與驗收員時，沿用當期交接紀錄，填入週報與資料版本、研究編號、待確認事項、負責角色及查證方式。旅遊研究員向場館、交通業者或主辦單位複查，旅行社方案負責人核對全團報價與適用條件，驗收員待修正後複驗。

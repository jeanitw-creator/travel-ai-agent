# PRD｜AI 台灣旅遊情報員 × 智慧行程推薦網站

## 1. 目標與範圍

讓旅客從每週旅遊情報進入偏好表單，取得可解釋的旅遊提案，再自行選擇是否向旅行社諮詢。第一版採純 **HTML、CSS、JavaScript** 與同站靜態資料，以規則產生推薦。這一版不依賴 Supabase、後端、登入、付費 API 或線上名單。使用靜態 HTTP 伺服器發布並測試。

週報可作為景點、活動和分眾文案素材。研究資料沒有可直接比價的旅行社方案，因此正式上線前須由旅行社補齊方案價格、包含項目、適用人數及有效期限。示範可以使用明確標示的模擬方案，正式模式排除模擬方案。 [週報](weekly-report.md) · [研究資料](../research/travel-data.json) · [來源清單](../research/sources.md)

## 2. 使用者與需求

| 使用者 | 主要任務 |
| --- | --- |
| 親子旅客 | 找孩子有興趣的主題，並確認步行、休息與同行人數。 |
| 情侶旅客 | 比較活動強度與旅行節奏，找兩人都感興趣的方案。 |
| 熟齡旅客 | 選看展、賞花等主題，確認必要步行上限與設施。 |
| 旅行社編輯與業務 | 查核來源、補齊方案成本，依旅客自行提供的摘要跟進。 |

## 3. 頁面與功能

| 頁面 | 功能 |
| --- | --- |
| 首頁／週報 | 顯示報導期間、查詢日、三類客群入口與「開始選行程」。已過期內容僅供回顧，標示原因，移除對應推薦入口。 |
| 偏好表單 | 必填旅遊對象、出發日期、同行人數、全團預算上限、天數及至少一種旅遊風格。提供選填目的地、出發地、最長連續步行時間及必需設施。目的地和出發地各可選一個縣市或「不限」。日期以台北時間解讀。輸入錯誤時顯示欄位層級訊息並保留原輸入，補齊後才執行比對。 |
| 推薦結果／方案詳情 | 顯示已套用的條件、最多三個推薦、推薦理由、總價或區間、估價範圍、分日內容、注意事項與來源。可回到表單調整並保留當前輸入。 |
| 諮詢摘要 | 顯示可複製的對象、日期、天數、人數、預算、風格、目的地、出發地、步行或設施限制與已選方案。聯絡資訊由旅客透過旅行社的官方聯繫管道自行提供。待旅行社提供有效網址後，顯示連結供旅客自行開啟，網址不附表單內容。 |

同次操作的偏好只保留在前端記憶體。刷新或離開後清除。諮詢摘要不寫入網址、瀏覽器儲存或第三方服務；複製僅在旅客按下按鈕時執行，受限時顯示可手動複製的文字。前端與 Git 不置入憑證或真實名單。

## 4. 預算與推薦邏輯

**預算單位**是新臺幣（TWD）元，表示同行旅客全團、全行程天數的總上限。人數另填。畫面例示「4 人、2 天，全團最多 NT$16,000」。旅客預算為正整數；方案費用為非負整數金額或最小至最大區間，價格須適用於該人數及日期。須列明住宿、交通、餐食、門票與其他必要支出是否包含。必要費用缺價或人數報價不明時標示「價格待確認」，禁止假設為零。可選加購另列，不計入比較口徑。若現有報價僅是每人或每晚價格，旅行社須依適用人數、天數及費用條款核算為全團總額後才能比對。

1. **驗證輸入**。人數與天數為正整數，出發日期不得早於台北當日；天數從出發日算第 1 日。風格選項為親子共學、工藝文化、自然攝影、戶外騎行、藝文觀展、賞花散步。
2. **先篩必要條件**。對象、天數、人數範圍、適用日期、有效費用及旅客明示的步行或設施限制都要符合。涉及活動時，依方案的第幾日換算實際到訪日，須落在官方展期及適用場次。所選出發日到旅程結束都須落在方案適用出遊日期內；報價另須在搜尋當下有效且明確適用所選出遊日期。若必需設施或步行條件缺資料，不能視為符合。
   - 指定目的地時，分日行程至少有一站位於該縣市。指定出發地時，方案須支援從該縣市出發，且比較的總價須適用該出發地。選「不限」時略過該縣市篩選，結果仍須列明總價對應的出發地或集合地。
   - 旅客設定步行上限時，以方案所有必要路段中的最長連續步行分鐘數比對。旅客指定多項必需設施時，每項都須在相關停留點及動線可用。
3. **再比預算及風格**。固定總價以該金額比較；區間以上限比較。上限等於旅客預算即可入選。至少命中一項所選風格，依命中數由多至少、全團價格上限由低至高、方案唯一 ID 字典序排列，顯示前三筆。卡片說明命中的風格與已通過的必要條件。
4. **零筆及讀取失敗分開**。零筆時顯示「目前沒有符合條件且已核對的方案」，依資料列出可核實的原因，例如日期不合、預算不足、必要資料待確認，或目前尚無已定價方案。保留輸入，提供修改日期、天數、預算或風格，以及複製諮詢摘要的入口。調整與重新查詢均由旅客觸發；必要限制不會自動放寬。資料無法載入時顯示「暫時無法讀取方案」及重試。

## 5. 資料欄位與狀態

| 資料 | 必要欄位 |
| --- | --- |
| 週報 | 標題、報導起訖、查詢日期、分眾摘要、研究 ID、官方來源。 |
| 景點／活動 | 沿用 `id`、`name`、`type`、`region`、`features`、`audiences`、`activityDates`、`status`、`sources`（含網址與查詢日）、`checkedOn`、`visitNotes`，另為需定期複查的欄位加上 `reviewBy`。活動起訖皆含當日；常設景點日期標「不適用」。 |
| 旅行社方案 | `id`、名稱、旅遊對象、風格、天數、適用人數上下限、適用出遊起訖、分日景點及研究 ID、費用幣別及口徑、全團價格上下限、適用人數的報價條件、包含與不含項目、報價查詢日及有效截止日、各必要條件狀態、查核期限與來源、模擬標記。 |
| 方案的行程限制 | 出發地或集合地、適用報價對應的出發地、各站目的地縣市、必要路段最長連續步行分鐘數、相關停留點與動線的設施狀態。 |
| 欄位查核紀錄 | 欄位名稱、狀態、來源網址、台北查詢日、適用期間或複查截止日。待確認時加記問題、負責角色及查證方式，來源缺漏時標示「來源待確認」。 |
| 旅客輸入 | 對象、人數、全團最高預算、天數、風格、出發日，選填目的地、出發地、連續步行分鐘上限與必需設施。 |

- **已驗證**。卡片及詳情附來源、查詢日期與適用條件。活動展期尚未到時標「即將開始」，符合旅客計畫日期者仍可比對。
- **已過期**。台北當日已晚於活動截止日、報價截止日或編輯設定的 `reviewBy` 日期時，顯示「已過期」與對應日期。週報保留原文供回顧；受影響的方案不進入正式推薦。展期內仍須依旅客實際到訪日查驗。
- **待確認**。必需欄位缺值、查不到查核期限、來源衝突或尚待當日公告時，標在受影響欄位旁，例如「價格待確認」「木棧道通行待確認」。顯示原查詢日期、來源、問題及下一步。若涉及費用、日期、安全、開放或旅客必要條件，從正式推薦排除；非必要選配待確認時可保留方案，並在卡片明示。已過期和待確認可分別標在不同欄位。
- **模擬資料**。獨立資料模式，頁首、方案卡與複製摘要都顯示「模擬資料」。真實方案與模擬方案分開。研究紀錄的「已驗證」只適用於已查核欄位，方案仍須另有價格與成行條件。

上架前由旅遊研究員重新查核票價、營業時間、交通、活動及開放狀態，旅行社方案負責人重核全團價格與適用條件。週報與推薦資料共用研究編號，查核結果填入同一期交接紀錄，驗收員依更新後的資料複驗。 [每週交接紀錄](weekly-handoff.md)

## 6. 響應式版型

- **320–767 px**。單欄表單與卡片，來源與長文字可換行，主要操作提供足夠觸控空間。
- **768–1023 px**。表單視欄位寬度採一至二欄，結果採最多兩欄。
- **1024 px 以上**。內容區置中，表單可雙欄，結果採最多三欄。每張卡共用標題、費用、理由、注意事項與來源的順序。
- 所有尺寸使用醒目文字狀態標籤、鍵盤焦點、明確表單標籤及錯誤提示。結果更新時提供輔助技術可感知的訊息。

## 7. 驗收條件

| 案例 | 可驗收結果 |
| --- | --- |
| 三類客群 | 使用標示的測試方案，親子、情侶、熟齡各能從週報完成推薦、看懂理由與來源、回填修改條件。 |
| 預算邊界 | 預算 NT$16,000 時，上限 NT$16,000 的四人方案入選；上限 NT$16,001、只適用兩人或必需費用缺價者不入選。 |
| 日期邊界 | 活動最後一天可比對；計算出的實際到訪日晚一天即排除。用方案第 2 日案例確認未以出發日代替到訪日。 |
| 地點與必要限制 | 指定目的地、出發地及步行上限時，逐一驗證縣市不符、報價不適用出發地、步行超限及必需設施未查證的方案均被排除。選「不限」時，結果仍顯示報價所用的出發地或集合地。 |
| 待確認與過期 | 模擬台北日期跨過截止日，受影響方案退出推薦，週報仍可查看且有狀態。高美濕地木棧道未核實時，含該必要行程的方案不入選。 |
| 排序及風格 | 三個以上符合方案依風格命中、價格及 ID 排序，顯示前三；零命中不列入。 |
| 零筆、載入失敗與諮詢 | 零筆保留原輸入並可手動調整，資料失敗有重試訊息；偏好摘要可手動複製，查驗無自動傳送或儲存個資。 |
| 裝置與可及性 | 以 320、768、1280 px 驗證表單、卡片和來源不橫向溢出，可用鍵盤完成流程，狀態可透過文字識別。 |
| 資料來源與工作範圍 | 正式模式不混入模擬資料，日期與原研究或有效官方公告一致。檢查只有靜態 HTML、CSS、JavaScript 與資料，前端無 Supabase、憑證或真實旅客名單。 |
